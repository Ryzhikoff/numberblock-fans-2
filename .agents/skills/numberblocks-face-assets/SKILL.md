# Numberblocks Face Assets

Создавай новое лицо только после изучения исходного блока. Результат должен выглядеть
как новое выражение того же персонажа, а не как универсальное лицо, наложенное на тело.

## Исходник обязателен

Перед генерацией или редактированием:

1. Найди исходный общий префаб блока, материал его лица и текстуру.
2. Просмотри текстуру и устройство фронтальных Renderer/Transform в префабе.
3. Зафиксируй число и форму глаз, рот, аксессуары, палитру, пропорции, отступы и
   положение лица на теле.
4. Используй оригинальную текстуру как edit target или строгий reference image.

Не заменяй характерные признаки более привычной анатомией. Известные инварианты:

- у Numberblock 100 один квадратный глаз с квадратной белой областью и круглым зрачком;
- у Numberblock 50 два овальных глаза, звезда вокруг левого глаза и синяя изогнутая шляпа.

Для других блоков сначала определи их инварианты по оригиналу. Примеры выше не являются
шаблоном для всех персонажей.

## Требования к изображению

- Формат — RGBA PNG с настоящим альфа-каналом.
- Вне элементов лица alpha должна быть равна нулю.
- Один файл содержит одно законченное выражение одного персонажа.
- Не рисуй фон, тело блока, цветную подложку, белый или чёрный прямоугольник.
- Не рисуй шахматную сетку прозрачности. Она не является прозрачностью.
- Не добавляй ореол, свечение, дымку, тень или полупрозрачное пятно вокруг лица,
  если эффект не был явно запрошен.
- Не добавляй текст и водяные знаки.
- Сохраняй стиль, цвета, толщину контуров и сглаживание оригинала.
- Сохраняй относительные размеры, интервалы и расположение элементов лица.

Если лицо заменяет оверлей существующего блока, итоговый canvas обязан иметь точные
пиксельные размеры оригинальной face-текстуры. При необходимости после генерации допустимы
только механические операции: resize/pad до исходного canvas и очистка ошибочного
низкоальфа-ореола. Они не должны творчески перерисовывать лицо или смещать его элементы.

Для нового составного блока выбирай аспект canvas по реальной фронтальной геометрии тела и
оставляй прозрачные поля, достаточные для размещения всего лица без обрезки.

Когда нужен AI-generated raster, также используй навык `imagegen` и соблюдай его workflow.
Невалидный результат не импортируй: повтори генерацию с явным требованием alpha zero.
Если встроенная генерация не может выдать корректный файл, не переходи скрыто на CLI/API;
следуй правилу fallback из `imagegen`.

## Интеграция в Unity

Не изменяй общий исходный префаб или его материалы. Создавай сценовые варианты в:

```text
Assets/Prefabs/Blocks/Scene<number>/FaceTextures/
Assets/Prefabs/Blocks/Scene<number>/Materials/
Assets/Prefabs/Blocks/Scene<number>/Prefabs/
```

Рекомендуемые имена:

```text
<Block>_<Expression>.png
<Block>_<Expression>_Transparent.mat
<Block>_<SceneRole>.prefab
```

Новый face overlay должен совпадать с исходной фронтальной плоскостью по local X/Y,
localRotation и localScale. Для защиты от z-fighting разрешён только небольшой сдвиг по
нормали этой плоскости; не вычисляй его от центра всего тела, поскольку лицо может быть
расположено не по центру.

- Если исходное лицо уже является отдельным прозрачным quad, дублируй его для новых
  выражений и переключай активный слой.
- Если лицо запечено во фронтальную текстуру, используй соответствующий чистый оригинальный
  материал тела на фронте и отдельный прозрачный overlay поверх него.
- Отключай отбрасывание и приём теней у face overlay.
- Используй прозрачный render queue, `SrcAlpha/OneMinusSrcAlpha` и `ZWrite = 0`.

Настройки TextureImporter для face PNG:

- `Texture Type = Default`;
- `Alpha Source = From Input`;
- `Alpha Is Transparency = true`;
- mipmaps выключены;
- `NPOT Scale = None`;
- `Wrap Mode = Clamp`;
- `Filter Mode = Bilinear`;
- compression выключена для сценовых лиц.

Всегда сохраняй созданные Unity `.meta` вместе с PNG, материалом и prefab-вариантом.

## Проверка перед завершением

Проверь все наблюдаемые инварианты:

1. PNG имеет RGBA-каналы, ожидаемые pixel width/height и прозрачные четыре угла.
2. В canvas одновременно есть достаточно видимых и действительно прозрачных пикселей.
3. Композит PNG на ярком контрастном фоне не показывает шахматку, прямоугольник, ореол или
   мусор по краям.
4. Анатомия совпадает с оригиналом: число и форма глаз, аксессуары и узнаваемые признаки.
5. Transform оверлея совпадает с исходной face-плоскостью по X/Y, rotation и scale.
6. Общий исходный prefab/material не изменён; сцена использует отдельный вариант.
7. Unity компилируется, статическая проверка проходит, а затронутая сцена просмотрена в
   Play Mode на ключевых выражениях и переходах.

финальных промптов, способ генерации и результаты проверки прозрачности/Unity.
